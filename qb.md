# Operating Systems - Comprehensive Test Questions and Answers

## Chapter 1: Introduction

### Section A: Terminology and Definitions

**Q1: What are the four main components of a computer system?**

**Answer:**
The four main components of a computer system are:
1. **Hardware** - Provides basic computing resources (CPU, memory, I/O devices)
2. **Operating System** - Controls and coordinates use of hardware among various applications and users
3. **Application Programs** - Define the ways in which system resources are used to solve computing problems (word processors, compilers, web browsers, database systems, video games)
4. **Users** - People, machines, and other computers that interact with the system

---

**Q2: Define the term "kernel" in the context of operating systems.**

**Answer:**
The kernel is "the one program running at all times on the computer" and is the core part of the operating system. It manages system resources, provides essential services, and controls hardware. Everything else is either a system program (ships with the OS but is not part of the kernel) or an application program.

---

**Q3: What is an interrupt? Explain the difference between hardware interrupts, software interrupts, traps, and exceptions.**

**Answer:**
An **interrupt** is a signal that transfers control to the interrupt service routine, temporarily suspending normal program execution.

- **Hardware interrupt**: Generated by hardware devices (I/O controllers) to signal completion of an operation or other events
- **Software interrupt**: Generated by running programs, also called traps or exceptions
- **Trap/Exception**: A software-generated interrupt caused either by an error (e.g., division by zero) or a user request (system call)

The interrupt architecture must save the address of the interrupted instruction so execution can resume later.

---

**Q4: What is the bootstrap program and where is it stored?**

**Answer:**
The **bootstrap program** is the initial program loaded at power-up or reboot that:
- Initializes all aspects of the system
- Loads the operating system kernel and starts execution
- Is typically stored in ROM (Read-Only Memory) or EPROM (Erasable Programmable Read-Only Memory)
- Generally known as firmware

---

**Q5: Explain the role of the device controller and device driver.**

**Answer:**
- **Device Controller**: Hardware component in charge of a particular device type, with a local buffer for data transfer
- **Device Driver**: Operating system software that manages a specific device controller type, providing a uniform interface between the controller and the kernel

The CPU moves data between main memory and local buffers, and device controllers inform the CPU of operation completion through interrupts.

---

**Q6: What is the interrupt vector?**

**Answer:**
The **interrupt vector** is a table that contains the addresses of all the interrupt service routines. When an interrupt occurs, control transfers to the appropriate service routine through this vector.

---

**Q7: What is meant by "an operating system is interrupt driven"?**

**Answer:**
An operating system is interrupt driven because it relies on interrupts to respond to events:
- I/O completions
- User program requests (system calls)
- Error conditions
- Timer expirations

The OS only performs actions when interrupted, rather than continuously polling for events.

---

### Section B: Computer System Organization

**Q8: Describe the general organization of a computer system and the role of interrupts.**

**Answer:**
**Computer system organization:**
- One or more CPUs and device controllers connected through a common bus
- Access to shared memory
- Concurrent execution of CPUs and devices competing for memory cycles

**Role of interrupts:**
- Device controllers inform the CPU that they've finished operations by causing interrupts
- Interrupts transfer control to interrupt service routines via the interrupt vector
- Interrupt architecture saves the address of the interrupted instruction
- Polling or vectored interrupt systems determine which type of interrupt occurred
- Separate code segments determine appropriate actions for each interrupt type

---

**Q9: Describe the components in a modern, multiprocessor computer system.**

**Answer:**
Modern multiprocessor systems include:

**Types:**
- **Asymmetric Multiprocessing**: Each processor is assigned a specific task
- **Symmetric Multiprocessing (SMP)**: Each processor performs all tasks

**Components:**
- Multiple processor cores (multi-chip and multicore)
- Chassis containing multiple separate systems
- Shared memory and I/O resources

**Advantages:**
1. **Increased throughput** - More work done in less time
2. **Economy of scale** - Sharing resources reduces costs
3. **Increased reliability** - Graceful degradation or fault tolerance

**NUMA (Non-Uniform Memory Access)**: System where memory access time depends on memory location relative to the processor.

---

**Q10: What is the difference between multiprogramming and timesharing (multitasking)?**

**Answer:**
**Multiprogramming (Batch system):**
- Organizes jobs so CPU always has one to execute
- Multiple jobs kept in memory
- One job selected via job scheduling
- When job waits (for I/O), OS switches to another job
- Goal: Keep CPU and I/O devices busy

**Timesharing (Multitasking):**
- Logical extension of multiprogramming
- CPU switches jobs so frequently users can interact with each job
- Creates interactive computing
- Response time should be < 1 second
- Each user has at least one program executing in memory (process)
- Uses CPU scheduling and virtual memory

---

**Q11: Explain the transition from user mode to kernel mode.**

**Answer:**
**Dual-mode operation:**
- **User mode**: Limited access to resources, non-privileged instructions only
- **Kernel mode**: Full access to hardware and resources, privileged instructions executable

**Transition:**
1. System call made by user program
2. Mode bit changed from user to kernel
3. OS executes privileged instructions in kernel mode
4. System call returns, resets mode bit to user mode

**Timer:**
- Prevents infinite loops or process hogging resources
- Set to interrupt computer after a time period
- Uses a counter decremented by the physical clock
- Setting counter is a privileged instruction

**Multi-mode support**: Increasingly CPUs support virtual machine manager (VMM) mode for guest VMs.

---

### Section C: Operating System Functions

**Q12: What is the role of the operating system as a resource allocator?**

**Answer:**
The OS acts as a resource allocator:
- Manages all computer resources (CPU cycles, memory, I/O devices, files)
- Makes efficient use of hardware
- Allocates resources to competing users and processes
- Controls and coordinates use of hardware among applications and users
- For shared computers (mainframes/minicomputers): must keep all users happy
- For dedicated systems (workstations): users have dedicated resources but frequently use shared resources from servers

---

**Q13: What is the difference between an operating system, system programs, and application programs?**

**Answer:**
- **Operating System**: Includes the kernel and essential system software
- **Kernel**: The program running at all times on the computer
- **System Programs**: Ship with the OS but are not part of the kernel (shells, compilers, text editors, system utilities)
- **Application Programs**: All programs not associated with the OS (word processors, web browsers, games)

**Middleware**: Software frameworks providing additional services to application developers (databases, multimedia, graphics).

---

**Q14: Explain the role of caching in computer systems.**

**Answer:**
**Caching** is copying information into faster storage systems temporarily:

- Information in use copied from slower to faster storage
- Faster storage (cache) checked first for information
- If present, information used directly from cache (fast)
- If not, data copied to cache and used there

**Cache management considerations:**
- Cache size and replacement policy are important design problems
- Cache is smaller than storage being cached
- Movement between storage hierarchy levels can be explicit or implicit
- Required for maintaining performance across storage hierarchy

**Cache coherency:** In multiprocessor environments, hardware must ensure all CPUs have the most recent value in their cache.

---

**Q15: What is virtual memory and why is it important?**

**Answer:**
**Virtual memory** allows execution of processes not completely in memory:
- Programs can be larger than physical memory
- Parts of programs are swapped in and out as needed
- Enables efficient multitasking
- Processes don't need to fit entirely in memory

**Swapping**: Moving processes in and out of memory to run them.

---

### Section D: Storage and Memory

**Q16: Explain the storage hierarchy, including characteristics of each level.**

**Answer:**
Storage hierarchy organized by:

| Level | Name | Typical Size | Access Time (ns) | Bandwidth (MB/sec) | Managed by |
|-------|------|--------------|------------------|-------------------|------------|
| 1 | Registers | <1 KB | 0.25-0.5 | 20,000-100,000 | Compiler |
| 2 | Cache | <16 MB | 0.5-25 | 5,000-10,000 | Hardware |
| 3 | Main Memory | <64 GB | 80-250 | 1,000-5,000 | OS |
| 4 | Solid-State Disk | <1 TB | 25,000-50,000 | 500 | OS |
| 5 | Magnetic Disk | <10 TB | 5,000,000 | 20-150 | OS |

**Implementation technologies:**
- Registers: Custom memory with multiple ports CMOS
- Cache: On-chip or off-chip CMOS SRAM
- Main Memory: CMOS SRAM
- SSD: Flash memory
- Magnetic Disk: Magnetic recording

---

**Q17: Define the following storage units: bit, byte, word, KB, MB, GB, TB, PB.**

**Answer:**
- **Bit**: Basic unit of computer storage (0 or 1)
- **Byte**: 8 bits, the smallest convenient chunk of storage on most computers
- **Word**: A computer architecture's native unit of data (one or more bytes)
- **KB (Kilobyte)**: 1,024 bytes (or ~1,000 bytes in some contexts)
- **MB (Megabyte)**: 1,024² = 1,048,576 bytes (or ~1 million bytes)
- **GB (Gigabyte)**: 1,024³ = 1,073,741,824 bytes (or ~1 billion bytes)
- **TB (Terabyte)**: 1,024⁴ bytes (or ~1 trillion bytes)
- **PB (Petabyte)**: 1,024⁵ bytes (or ~1 quadrillion bytes)

**Note**: Networking measurements are given in bits (not bytes) because networks move data a bit at a time.

---

**Q18: What is Direct Memory Access (DMA)?**

**Answer:**
**Direct Memory Access (DMA)** is used for high-speed I/O devices:
- Device controller transfers blocks of data from buffer storage directly to main memory without CPU intervention
- Only one interrupt is generated per block, rather than one interrupt per byte
- Used for devices able to transmit information at close to memory speeds
- Significantly reduces CPU overhead for I/O operations

---

### Section E: Security and Protection

**Q19: Explain the concepts of protection and security in operating systems.**

**Answer:**
**Protection**: Any mechanism for controlling access of processes or users to resources defined by the OS.

**Security**: Defense of the system against internal and external attacks.

**Security threats include:**
- Denial-of-service attacks
- Worms and viruses
- Identity theft
- Theft of service

**User identification mechanisms:**
- **User IDs (Security IDs)**: Name and associated number, one per user
- **Group identifiers (Group IDs)**: Allows set of users to be defined and controls managed
- **Privilege escalation**: Allows user to change to effective ID with more rights

---

**Q20: What is virtualization in the context of operating systems?**

**Answer:**
**Virtualization** allows operating systems to run applications within other OSes:
- **Emulation**: Used when source CPU type differs from target type (slowest method)
- **Virtualization**: OS natively compiled for CPU, running guest OSes also natively compiled
- **VMM (Virtual Machine Manager)**: Provides virtualization services

**Use cases:**
- Laptops and desktops running multiple OSes for exploration or compatibility
- Developing apps for multiple OSes without multiple systems
- QA testing applications without multiple systems
- Managing compute environments within data centers

**VMM types:**
- Can run natively (also as host)
- VMware ESX and Citrix XenServer are examples

### Section F: Computing Environments

**Q21: Compare client-server computing with peer-to-peer computing.**

**Answer:**
**Client-Server Computing:**
- Dumb terminals supplanted by smart PCs
- Servers respond to requests generated by clients
- **Compute-server**: Provides interface to request services (e.g., database)
- **File-server**: Provides interface to store and retrieve files

**Peer-to-Peer (P2P) Computing:**
- Does not distinguish clients and servers
- All nodes considered peers
- Each node may act as client, server, or both
- Node must join P2P network
- Registers service with central lookup service or broadcasts for service discovery
- Examples: Napster, Gnutella, Voice over IP (VoIP) like Skype

---

**Q22: Explain cloud computing and its service models.**

**Answer:**
**Cloud Computing**: Delivers computing, storage, even apps as a service across a network

**Types:**
- **Public cloud**: Available via Internet to anyone willing to pay
- **Private cloud**: Run by a company for internal use
- **Hybrid cloud**: Includes both public and private cloud components

**Service Models:**
- **SaaS (Software as a Service)**: Applications available via Internet (e.g., word processor)
- **PaaS (Platform as a Service)**: Software stack ready for application use (e.g., database server)
- **IaaS (Infrastructure as a Service)**: Servers or storage available over Internet (e.g., backup storage)

Cloud computing environments are composed of traditional OSes, VMMs, and cloud management tools.

**Real-time embedded systems** are the most prevalent form of computers:

**Q25: List and explain the user-oriented services provided by an operating system.**

**System-oriented services:**

1. **Resource Allocation**: Allocates CPU cycles, main memory, file storage, I/O devices among multiple users/jobs

### Section C: System Calls

**Q28: What are system calls and how are they typically accessed?**

**Answer:**
**System calls** are the programming interface to services provided by the OS:
- Typically written in high-level languages (C or C++)
- Mostly accessed via high-level Application Programming Interfaces (APIs)
- Provide requests for OS services from user programs

**Common APIs:**
- **Win32 API**: For Windows systems
- **POSIX API**: For POSIX-based systems (UNIX, Linux, Mac OS X)
- **Java API**: For Java Virtual Machine (JVM)

**Example**: The `read()` function in UNIX/Linux:
- Requires `#include <unistd.h>`
- Parameters: `int fd` (file descriptor), `void *buf` (buffer), `size_t count` (bytes to read)
- Returns: bytes read, 0 for end of file, -1 for error

---

**Q29: Explain how parameters are passed to system calls.**

**Answer:**
Three general methods for passing parameters:

1. **Registers**: Simplest method, pass parameters in registers
   - May not work if more parameters than registers

2. **Block/Table in Memory**: 
   - Parameters stored in a block or table in memory
   - Address of block passed as parameter in a register
   - Used by Linux and Solaris
   - No limit on number or length of parameters

3. **Stack**:
   - Parameters placed/pushed onto stack by program
   - Popped off by operating system
   - No limit on number or length of parameters

---

**Q30: List the major categories of system calls and provide examples.**

**Answer:**
**Major categories of system calls:**

1. **Process Control**:
   - Create/terminate process
   - Load/execute
   - Get/set process attributes
   - Wait for time/wait event/signal event
   - Allocate/free memory
   - Debugger for determining bugs
   - Locks for managing shared data

2. **File Management**:
   - Create/delete file
   - Open/close file
   - Read/write/reposition
   - Get/set file attributes

3. **Device Management**:
   - Request/release device
   - Read/write/reposition
   - Get/set device attributes
   - Logically attach/detach devices

4. **Information Maintenance**:
   - Get/set time/date
   - Get/set system data
   - Get/set process, file, or device attributes

5. **Communications**:
   - Create/delete communication connection
   - Send/receive messages (message passing model)
   - Create/gain access to memory regions (shared memory model)
   - Transfer status information
   - Attach/detach remote devices

6. **Protection**:
   - Control access to resources
   - Get/set permissions
   - Allow/deny user access

### Section E: Linkers and Loaders

**Q33: Explain the roles of linker and loader in program execution.**

**Answer:**
**Source code → Object files → Executable → Running program**

**Linker:**
- Combines relocatable object files into a single binary executable file
- Brings in necessary libraries
- Resolves symbol references between object files
- Modern systems use dynamically linked libraries (DLLs) loaded as needed and shared

**Loader:**
- Brings program from secondary storage into memory
- Performs relocation (assigns final addresses to program parts)
- Adjusts code and data to match addresses
- Modern general-purpose systems use dynamic linking

- **ABI (Application Binary Interface)**: Architecture equivalent of API; defines how binary components interface for a given OS on a given architecture
- **System Calls**: The actual requests to the OS kernel through the system-call interface

### Section F: Operating System Design and Implementation

**Q35: Explain the difference between policy and mechanism in OS design.**

**Answer:**
**Policy**: What will be done? (Decisions)
**Mechanism**: How to do it? (Implementation)

**Principle**: Separation of policy from mechanism
- Allows maximum flexibility if policy decisions need to change
- Example: Timer provides mechanism; policy determines its use

**Design goals:**
- **User goals**: Convenient, easy to learn, reliable, safe, fast
- **System goals**: Easy to design/implement/maintain, flexible, reliable, error-free, efficient

### Section G: Operating System Structure

**Q37: Compare and contrast monolithic, layered, microkernel, and modular OS structures.**

**Answer:**
**1. Simple/Monolithic Structure:**
- Example: MS-DOS, Original UNIX
- All functionality in a single kernel
- Limited structuring
- Everything below system-call interface and above hardware
- Large number of functions at one level

**2. Layered Structure:**
- OS divided into layers (levels), each built on lower layers
- Layer 0: Hardware; Layer N: User interface
- Each layer uses services of only lower-level layers
- Benefits: Modularity, easier to maintain
- Example: The THE operating system

**3. Microkernel Structure:**
- Moves as much from kernel into user space
- Communication via message passing
- Benefits: Easier to extend, port, more reliable, more secure
- Detriments: Performance overhead
- Example: Mach (used in Mac OS X kernel/Darwin)

**4. Modular Structure:**
- Loadable kernel modules (LKMs)
- Object-oriented approach
- Each core component separate
- Talks to others over known interfaces
- Loadable as needed
- Examples: Linux, Solaris

**5. Hybrid Structure:**
- Combines multiple approaches
- Linux/Solaris: Monolithic + modular for dynamic loading
- Windows: Mostly monolithic + microkernel for subsystem personalities
- Mac OS X: Hybrid, layered (Aqua UI, Cocoa, Mach microkernel + BSD Unix)

---

**Q38: Describe the structure of UNIX and Linux operating systems.**

**Answer:**
**UNIX Structure:**
- Two separable parts:
  - Systems programs
  - Kernel (everything below system-call interface and above hardware)
- Kernel provides: File system, CPU scheduling, memory management
- Large number of functions at one level

**Linux Structure:**
- Monolithic plus modular design
- Loadable kernel modules
- System-call interface to kernel

**Layers (from top to bottom):**
1. Users (shells, commands, compilers, interpreters, system libraries)
2. System-call interface to kernel
3. Kernel functions (signals, terminal handling, character I/O, file system, swapping, block I/O, CPU scheduling, page replacement, virtual memory)
4. Kernel interface to hardware
5. Hardware (terminal controllers, device controllers, memory controllers)

---

**Q39: Describe the structure of macOS and iOS operating systems.**

**Answer:**
**macOS Structure:**
- Hybrid, layered
- Aqua UI plus Cocoa programming environment
- Kernel (Darwin): Mach microkernel + BSD Unix parts
- I/O kit and dynamically loadable modules (kernel extensions)

**iOS Structure (Apple mobile OS):**
- Structured on Mac OS X with added functionality
- Runs on ARM CPU architecture (vs. Intel)
- Cocoa Touch: Objective-C API for developing apps
- Media services layer: Graphics, audio, video
- Core services: Cloud computing, databases
- Core operating system: Based on Mac OS X kernel

**Android Architecture (Open Handset Alliance/Google):**
- Open Source
- Based on Linux kernel (modified)
- Provides process, memory, device-driver management
- Adds power management
- Runtime environment: Core libraries + Dalvik virtual machine
- Apps developed in Java + Android API
- Libraries: WebKit (browser), SQLite (database), multimedia, smaller libc

### Section H: Building and Booting

**Q40: Explain the boot process of an operating system.**

**Answer:**
**Boot process steps:**

1. **Power initialization**: Execution starts at a fixed memory location

2. **Bootstrap loader/BIOS**: Small piece of code stored in ROM or EEPROM
   - Locates the kernel
   - Loads it into memory
   - Starts it

3. **Two-step process** (sometimes):
   - Boot block at fixed location loaded by ROM code
   - Boot block loads bootstrap loader from disk

4. **Modern replacement**: Unified Extensible Firmware Interface (UEFI)

5. **Common bootstrap loader**: GRUB
   - Allows selection of kernel from multiple disks
   - Supports different versions and kernel options

6. **Kernel loads**: System becomes running

7. **Boot states**: Loaders frequently allow various boot states (e.g., single user mode)

**Q41: How is the Linux kernel built and installed?**

**Answer:**
**Steps to build Linux kernel:**

1. Download Linux source code from http://www.kernel.org

2. Configure kernel: `make menuconfig`

3. Compile kernel: `make` → produces `vmlinux` (kernel image)

4. Compile kernel modules: `make modules`

5. Install kernel modules: `make modules_install`

## Chapter 3: Processes

### Section A: Process Concept

**Q43: Define a process and identify its components.**

**Answer:**
A **process** is a program in execution; process execution must progress in sequential fashion.

**Components of a process:**
1. **Text section**: Program code
2. **Current activity**: Program counter, processor registers
3. **Stack**: Temporary data (function parameters, return addresses, local variables)
4. **Data section**: Global variables
5. **Heap**: Memory dynamically allocated during run time

**Process vs Program:**
- **Program**: Passive entity stored on disk (executable file)
- **Process**: Active entity when program is loaded into memory
- One program can be several processes (multiple users executing same program)

---

**Q44: What information is stored in the Process Control Block (PCB)/Task Control Block?**

**Answer:**
The PCB (or task control block) contains:

1. **Process state**: Running, waiting, ready, etc.
2. **Program counter**: Location of next instruction to execute
3. **CPU registers**: Contents of all process-centric registers
4. **CPU scheduling information**: Priorities, scheduling queue pointers
5. **Memory-management information**: Memory allocated to the process
6. **Accounting information**: CPU used, clock time elapsed, time limits
7. **I/O status information**: I/O devices allocated, list of open files

**Linux representation**: `task_struct` structure
```
pid_t_pid;          // process identifier
long state;         // state of the process
unsigned int time_slice; // scheduling information
struct task_struct *parent; // this process's parent
struct list_head children; // this process's children
struct files_struct *files; // list of open files
struct mm_struct *mm; // address space of this process
```

---

**Q45: What are the five process states?**

**Answer:**
1. **New**: The process is being created
2. **Running**: Instructions are being executed
3. **Waiting**: The process is waiting for some event to occur (e.g., I/O)
4. **Ready**: The process is waiting to be assigned to a processor
5. **Terminated**: The process has finished execution

**Transitions between states:**
- New → Ready (admitted)
- Ready → Running (scheduler dispatch)
- Running → Waiting (I/O or event wait)
- Waiting → Ready (I/O or event completion)
- Running → Terminated (exit/termination)
- Running → Ready (interrupt/time slice expiration)

### Section B: Process Scheduling

**Q46: Explain the concept of a context switch and its overhead.**

**Answer:**
**Context switch**: When the CPU switches from one process to another, the system must:
1. Save the state of the old process (PCB)
2. Load the saved state for the new process (PCB)

**Overhead:**
- Context-switch time is overhead; system does no useful work while switching
- More complex OS and PCB → longer context switch
- Time dependent on hardware support
- Some hardware provides multiple sets of registers per CPU → multiple contexts loaded at once

---

**Q47: What are scheduling queues and how do processes migrate between them?**

**Answer:**
**Scheduling queues:**
1. **Ready queue**: All processes residing in main memory, ready and waiting to execute
2. **Wait queues**: Processes waiting for an event (e.g., I/O)

**Process migration:**
- New process → Ready queue
- Ready queue → Running (scheduler dispatch)
- Running → Wait queue (I/O or event wait)
- Wait queue → Ready queue (event completion)
- Running → Terminated (exit)

**Process scheduler**: Selects among available processes for next execution on CPU core

**Q48: How do mobile operating systems handle process scheduling differently?**

**iOS (early versions):**
- Only one process can run, others suspended
- Single foreground process controlled via user interface
- Multiple background processes (in memory, running but not on display)
- Limits: single, short task; receiving notifications; specific long-running tasks (audio playback)

**Android:**
- Runs foreground and background with fewer limits
- Background processes use a **service** to perform tasks
- Services can keep running even if background process is suspended
- Services have no user interface and small memory use

**Android Process Importance Hierarchy (from most to least important):**
1. Foreground process
2. Visible process
3. Service process
4. Background process
5. Empty process

Android terminates least important processes first to reclaim resources.

### Section C: Operations on Processes

**Q49: Explain process creation using fork() and exec() system calls in UNIX.**

**Answer:**
**fork()**:
- Creates a new process (child process) as a duplicate of the parent
- Returns:
  - `0` to the child process
  - Child's PID to the parent
  - Negative if error

**exec()**:
- Used after fork() to replace the process' memory space with a new program
- Loads a new program into the current process
- Multiple variants: `execlp`, `execvp`, etc.

**wait()**:
- Parent calls wait() for child to terminate
- Returns status information and PID of terminated process

**Example (simplified):**
```c
pid_t pid = fork();
if (pid == 0) {  // child process
    execlp("/bin/ls", "ls", NULL);
} else {         // parent process
    wait(NULL);
}
```

**Q50: How does process creation work in Windows using CreateProcess?**

**Answer:**
Windows uses `CreateProcess()` system call:
```c
CreateProcess(NULL,               // use command line
              "C:\\WINDOWS\\system32\\mspaint.exe",
              NULL,               // don't inherit process handle
              NULL,               // don't inherit thread handle
              FALSE,              // disable handle inheritance
              0,                  // no creation flags
              NULL,               // use parent's environment block
              NULL,               // use parent's existing directory
              &si,                // STARTUPINFO
              &pi)                // PROCESS_INFORMATION
```

**Key differences from UNIX:**
- `CreateProcess()` loads program into child process in one step (no fork/exec separation)
- Returns handle to process for waiting and cleanup
- Parent waits using `WaitForSingleObject()`
- Must close handles with `CloseHandle()`

**Q51: Explain process termination and what are zombie and orphan processes.**

**Answer:**
**Process termination** occurs when:
- Process executes last statement and calls `exit()`
- Returns status data from child to parent (via `wait()`)
- Process' resources are deallocated by OS

**Parent may terminate child using `abort()`** for reasons:
- Child exceeded allocated resources
- Task no longer required
- Parent is exiting and OS doesn't allow child to continue

**Zombie process**: Parent did not invoke `wait()` for terminated child
- Child process table entry remains
- Resources are released except PCB for status information

**Orphan process**: Parent terminated without invoking `wait()`
- May be adopted by `init` process (PID 1) in UNIX systems

**Cascading termination**: Some OSes terminate all children when parent terminates

Google Chrome uses multiprocess architecture with three process types:

1. **Browser process**: Manages user interface, disk and network I/O

2. **Renderer process**: Renders web pages, deals with HTML and JavaScript
   - A new renderer created for each website opened
   - Runs in sandbox restricting disk and network I/O
   - Minimizes effect of security exploits

3. **Plug-in process**: One for each type of plug-in

**Benefits:**
- Each tab is a separate process
- If one web site causes trouble, only that tab crashes
- Better security through sandboxing
- Improved stability

**Q53: Define independent and cooperating processes, and list reasons for process cooperation.**

**Answer:**
**Independent process**: Cannot affect or be affected by execution of another process

**Cooperating process**: Can affect or be affected by execution of another process

**Reasons for cooperating processes:**

4. **Convenience**: Specialized processes for different tasks

**Q54: Compare and contrast shared memory and message passing IPC models.**

**Answer:**

| Aspect | Shared Memory | Message Passing |
|--------|--------------|-----------------|
| **Communication** | Direct memory access | Send/receive messages |
| **Control** | Under user processes | Managed by OS |
| **Speed** | Faster (no kernel involvement) | Slower (system call overhead) |

| **Implementation** | Create shared memory segment, map to address space | Send/receive primitives |
| **Capacity** | Can be unbounded or bounded | Fixed or variable message size |

**Q55: Explain the producer-consumer problem and bounded buffer solution.**

**Answer:**
**Producer-Consumer problem**: Producer process produces information consumed by consumer process

**Bounded buffer**: Fixed buffer size

**Shared data (simplified):**
```c
#define BUFFER_SIZE 10
typedef struct { ... } item;
item buffer[BUFFER_SIZE];
int in = 0;  // next free position
int out = 0; // first full position
```

**Producer:**
```c
while (true) {
    /* produce an item in next_produced */
    while (((in + 1) % BUFFER_SIZE) == out)
        ; // do nothing (buffer full)
    buffer[in] = next_produced;
    in = (in + 1) % BUFFER_SIZE;
}
```

**Consumer:**
```c
while (true) {
    while (in == out)
        ; // do nothing (buffer empty)
    next_consumed = buffer[out];
    out = (out + 1) % BUFFER_SIZE;
    /* consume the item in next_consumed */
}
```

**Note**: Solution only uses BUFFER_SIZE - 1 elements to distinguish full from empty.

**Q56: Explain the POSIX shared memory implementation.**

**Answer:**
**POSIX Shared Memory steps:**

1. **Create/Open shared memory segment**:
   ```c
   shm_fd = shm_open(name, O_CREAT | O_RDWR, 0666);
   ```

2. **Set size**:
   ```c
   ftruncate(shm_fd, SIZE);
   ```

3. **Memory-map**:
   ```c
   ptr = mmap(0, SIZE, PROT_WRITE, MAP_SHARED, shm_fd, 0);
   ```

4. **Write to shared memory** using returned pointer:
   ```c
   sprintf(ptr, "%s", message_0);
   ptr += strlen(message_0);
   sprintf(ptr, "%s", message_1);
   ```

5. **Read from shared memory**:
   ```c
   ptr = mmap(0, SIZE, PROT_READ, MAP_SHARED, shm_fd, 0);
   printf("%s", (char*)ptr);
   ```

6. **Remove**:
   ```c
   shm_unlink(name);
   ```

**Key functions**: `shm_open()`, `ftruncate()`, `mmap()`, `shm_unlink()`

**Q57: Explain the message passing IPC model and its variations.**

**Answer:**
**Message passing**: Processes communicate without shared variables via `send()` and `receive()` operations.

**Direct vs Indirect communication:**
- **Direct**: Processes name each other explicitly (`send(P, message)`, `receive(Q, message)`)
- **Indirect**: Messages sent/received from mailboxes/ports

**Synchronous (blocking) vs Asynchronous (non-blocking):**
- **Blocking send**: Sender blocked until message received
- **Blocking receive**: Receiver blocked until message available
- **Non-blocking send**: Sender continues immediately
- **Non-blocking receive**: Returns valid message or null

**Rendezvous**: Both send and receive are blocking

**Capacity options:**
1. **Zero capacity**: No messages queued
2. **Bounded capacity**: Finite length of n messages
3. **Unbounded capacity**: Infinite length

**Q58: Explain the Mach message passing system.**

**Answer:**
**Mach** uses message passing centric communication:

**Key structures**:
```c
struct message {
    mach_msg_header_t header;
    int data;
};
```

**Client sends:**
```c
mach_msg(&message.header,     // message header
         MACH_SEND_MSG,       // sending a message
         sizeof(message),     // size of message sent
         0,                   // maximum size of received message
         MACH_PORT_NULL,      // name of receive port
         MACH_MSG_TIMEOUT_NONE, // no time outs
         MACH_PORT_NULL);     // no notify port
```

**Server receives:**
```c
mach_msg(&message.header,     // message header
         MACH_RCV_MSG,        // receiving a message
         0,                   // size of message sent
         sizeof(message),     // maximum size of received message
         server,              // name of receive port
         MACH_MSG_TIMEOUT_NONE, // no time outs
         MACH_PORT_NULL);     // no notify port
```

**Q59: Explain Windows Local Procedure Calls (LPC) facility.**

**Q63: What are Remote Procedure Calls (RPC) and how do they work?**

### Section G: Additional Process Concepts

**Q64: What are threads and how do they differ from processes?**

**Answer:**
**Thread**: A single thread of execution within a process

**Single-threaded process**: Has one program counter specifying location of next instruction to execute; executes instructions sequentially

**Multi-threaded process**: Has one program counter per thread
- Multiple locations can execute simultaneously
- Multiple threads of control within same process
- Each thread has its own stack and registers
- Shared memory space and resources

**Process**: Has multiple parts (text, data, heap, stack)
- Typically has many processes (user and system) running concurrently
- Concurrency by multiplexing CPUs among processes/threads

**Q67: What is the relationship between program, process, and process state?**

- Passive entity stored on disk (executable file)
- Contains code and data

**Process**:

**Q68: Explain the process control block (PCB) and its role in context switching.**

- Created when process starts
- Updated during execution
- Used to save/restore process state

4. Resume execution of next process

**Q69: What is the difference between unbounded and bounded buffers?**

**Answer:**
**Unbounded buffer**:
- Places no practical limit on the size of the buffer
- Producer can always add items
- Consumer may wait for items

**Bounded buffer**:
- Fixed buffer size
- Producer must wait if buffer is full
- Consumer must wait if buffer is empty
- More practical for real systems

**Q70: Explain the concept of "rendezvous" in message passing.**

**Answer:**
**Rendezvous** occurs when both send and receive operations are blocking:
- Sender blocks until message is received
- Receiver blocks until a message is available
- Ensures both processes are synchronized at the communication point
- Provides both synchronization and communication

**Other combinations**:
- Send blocking, receive non-blocking
- Send non-blocking, receive blocking
- Both non-blocking (asynchronous)

**Q75: Compare process scheduling in batch systems vs time-sharing systems.**

**Answer:**
**Batch systems (Multiprogramming)**:
- Jobs scheduled without user interaction
- CPU switches jobs when one waits for I/O
- Goal: Keep CPU and I/O devices busy
- Less emphasis on response time

**Time-sharing systems (Multitasking)**:
- CPU switches jobs frequently for interactivity
- Response time should be < 1 second
- Each user has at least one process in memory
- Uses CPU scheduling algorithms to manage multiple processes
- Emphasizes fairness and responsiveness
