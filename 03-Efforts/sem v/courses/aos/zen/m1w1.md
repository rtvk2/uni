**Time & Memory Complexity Fundamentals**
___
**Core Concept & Intuition**
* **Time Complexity is NOT measured in seconds.** It is a measure of the **number of elementary instructions** your program executes relative to the input size ($N$).
* **The Adversarial Nature of DSA:** Online Judges (LeetCode, Codeforces) use test cases specifically designed to make your code hit Time Limit Exceeded (TLE) or Memory Limit Exceeded (MLE). Therefore, we almost exclusively care about the **Worst-Case** scenario.
* **The 1-Second Rule (Crucial Heuristic):** A standard C++ program can safely execute roughly **$10^8$ operations per second**.
* If your time limit is 1 second and $N = 10^5$, an $O(N^2)$ solution will take $10^{10}$ operations and **will TLE**. You need an $O(N \log N)$ or $O(N)$ solution.

**Order Notations (Asymptotics)**
We don't count exact instructions (e.g., $2N^2 + 3N + 1$). We analyze how the function grows as $N \rightarrow \infty$.
* **Big-O ($O$) - Upper Bound:** The maximum time the algorithm could possibly take. (The most important metric).
* **Omega ($\Omega$) - Lower Bound:** The minimum time the algorithm could take (Best-case).
* **Theta ($\Theta$) - Tight Bound:** When the upper and lower bounds are the exact same class.

**Simplification Rules:**
1. **Drop Constants:** $O(2N) \rightarrow O(N)$. Multiplying by a constant doesn't change the growth rate.
2. **Drop Lower-Order Terms:** $O(N^2 + 3N + 5) \rightarrow O(N^2)$. For huge inputs, the largest power dominates.

**Analyzing Iterative Code**
* **Sequential Code (Addition):** If you run one loop, and then another loop, you add their complexities. $O(N) + O(N^2) \rightarrow O(N^2)$ (Lower term dropped).
* **Nested Code (Multiplication):** If a loop runs *inside* another loop, you multiply them. A loop running $N$ times, containing a loop running $N$ times $\rightarrow O(N \times N) = O(N^2)$.
* **Independent Variables:** If loops depend on different inputs, keep them separate. Looping to $N$, then looping to $M \rightarrow O(N + M)$. Nested loop to $N$, inner loop to $M \rightarrow O(N \times M)$.

```cpp
// Example: Sequential vs Nested
int n = 1000;
// O(N)
for (int i = 0; i < n; i++) {
    // ...
}
// O(N^2)
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) { // Or j < i, still O(N^2) asymptotically
        // ...
    }
}

```

**Master Theorem (For Recursive Functions)**
Used to calculate the time complexity of "Divide and Conquer" algorithms.
**Standard Form:**
$$T(N) = A \cdot T(N/B) + O(N^C)$$
* **$A$**: Number of recursive subproblems you split the task into.
* **$B$**: The factor by which the input size is divided.
* **$O(N^C)$**: The work done *outside* the recursive calls (e.g., iterating to merge halves).

**The Shortcut Rule (As taught in the video):**
Calculate $N^{\log_B A}$ and compare it to $N^C$:
1. If **$N^{\log_B A} > N^C$** $\implies O(N^{\log_B A})$
2. If **$N^{\log_B A} < N^C$** $\implies O(N^C)$
3. If **$N^{\log_B A} == N^C$** $\implies O(N^C \log N)$

**Examples:**
* **Merge Sort:** $T(N) = 2 \cdot T(N/2) + O(N)$. $A=2, B=2, C=1$. $N^{\log_2 2} = N^1$, which equals $N^C$ ($N^1$). Result: **$O(N \log N)$**
* **Example 2:** $T(N) = 8 \cdot T(N/2) + O(N^3)$. $A=8, B=2, C=3$. $N^{\log_2 8} = N^3$, which equals $N^C$ ($N^3$). Result: **$O(N^3 \log N)$**
**Note (not in video):** The simplified Master Theorem presented above assumes the non-recursive work is strictly polynomial $O(N^C)$. If the extra work has a logarithmic term (e.g., $O(N^C \log N)$), the full mathematical Master Theorem handles it slightly differently, but the 3 rules above cover 95% of standard DSA problems.

**C++ Specific Gotchas & STL Complexities**
* **Hidden Complexities:** A single `for` loop looks like $O(N)$, but if you put an $O(N)$ operation *inside* it, it becomes $O(N^2)$.
* *Bad:* `array.insert(array.begin(), val)` inside a loop. Shifting elements in a `std::vector` is $O(N)$. Doing it $N$ times is $O(N^2)$.
* *Good:* `array.push_back(val)` is amortized $O(1)$.
* **Pass-by-Value vs. Pass-by-Reference:** Passing large data structures (like `std::vector` or `std::string`) to a recursive function *by value* creates a full copy every call, turning an $O(N)$ algorithm into $O(N^2)$ and guaranteeing Memory Limit Exceeded.
* **Always** pass by reference (`const vector<int>& nums`) in recursion/backtracking unless you explicitly need a modified copy.
* **Common STL Complexities:**
* `std::sort()`: **$O(N \log N)$**
* `std::unordered_map`: Average **$O(1)$**, Worst case $O(N)$ (due to hash collisions).
* `std::map` / `std::set` (Trees): **$O(\log N)$** per insertion/lookup.

**Modulo Arithmetic & Combinatorics**
___
**Core Concept & Intuition**

* **Modulo acts as a wrap-around:** When computing $A \pmod C$, you map any integer into a fixed space of $C$ values (from $0$ to $C-1$).
* **Congruence:** If $A \equiv B \pmod C$, it means $A$ and $B$ leave the same remainder when divided by $C$. This is mathematically equivalent to saying $C \mid (A - B)$ or $A = B + k \cdot C$.
* **Why we use it in DSA:** Problems ask for answers modulo a prime like $10^9 + 7$ to prevent integer overflow when dealing with massive dynamic programming results or combinatorics.

**Modulo Arithmetic Properties**

* **Addition:** $(A + B) \pmod C = ((A \pmod C) + (B \pmod C)) \pmod C$
* **Subtraction:** $(A - B) \pmod C = ((A \pmod C) - (B \pmod C)) \pmod C$
* **Multiplication:** $(A \times B) \pmod C = ((A \pmod C) \times (B \pmod C)) \pmod C$
* **Exponentiation:** $A^B \pmod C = ((A \pmod C)^B) \pmod C$
* **Division:** You **cannot** directly divide. $(A / B) \pmod C \neq ((A \pmod C) / (B \pmod C)) \pmod C$. You must use the Modulo Inverse instead.

**C++ Pitfall: Negative Modulo**

* In C++, the `%` operator calculates the remainder, not a true mathematical modulo. For negative numbers, $-3 \% 2$ evaluates to $-1$, not $1$.
* **The Fix:** To get the correct positive modulo, you add the mod value and modulo again.
* **Formula:** `(A % M + M) % M`
* **Rule of thumb:** Anytime you perform a subtraction modulo operation, wrap it in this formula to guarantee positive results.

**Binary Exponentiation**

* **Problem:** Calculating $A^B \pmod C$ naively takes $O(B)$ time. If $B = 10^9$, this will definitely TLE.
* **Concept:** We can compute this in **$O(\log B)$** time by looking at the binary representation of the power $B$.
* By squaring the base at each step and halving the power, we skip unnecessary multiplications.

```cpp
long long power(long long base, long long exp) {
    long long mod = 1e9 + 7;
    long long ans = 1;
    base = base % mod;
    while (exp > 0) {
        if (exp % 2 == 1) { 
            ans = (1LL * ans * base) % mod;
        }
        base = (1LL * base * base) % mod;
        exp = exp / 2;
    }
    return ans;
}

```

**Modulo Inverse & Fermat's Little Theorem**

* **Concept:** To divide $A$ by $B$ under modulo $P$, we multiply $A$ by the modulo inverse of $B$. $A / B \pmod P \equiv A \times B^{-1} \pmod P$.
* **Fermat's Little Theorem:** States that if $P$ is a prime number and $A$ is coprime to $P$, $A^{P-1} \equiv 1 \pmod P$.
* If we divide both sides by $A$, we get the formula for the modulo inverse: **$A^{-1} \equiv A^{P-2} \pmod P$**.
* **Heuristic:** To find the inverse of $B$ modulo $10^9 + 7$, you simply calculate $B^{10^9+5} \pmod{10^9+7}$ using the Binary Exponentiation function.
* **Time Complexity:** Computing the inverse takes **$O(\log P)$** time.

**Combinatorics ($nCr \pmod P$)**

* **Formula:** $nCr \pmod P = \frac{n!}{r!(n-r)!} \pmod P$.
* **Problem:** We must compute this fast for multiple test cases. Doing $O(N)$ work per query will TLE.
* **Strategy:** Precompute all factorials up to the maximum $N$ and store them in an array once. This takes **$O(N)$** time.
* For each query, retrieve $n!$, calculate the inverses of $r!$ and $(n-r)!$ using Fermat's Little Theorem, and multiply them together.
* **Time Complexity:** Precomputation is **$O(N)$**. Each individual query is answered in **$O(\log P)$** because of the inverse calculation.

```cpp
const int N = 100000;
long long fact[N + 1];

void precompute() {
    long long mod = 1e9 + 7;
    fact[0] = 1;
    for (int i = 1; i <= N; i++) {
        fact[i] = (fact[i - 1] * i) % mod;
    }
}

long long nCr(int n, int r) {
    if (r > n || r < 0) return 0;
    long long mod = 1e9 + 7;
    
    long long num = fact[n];
    long long den1 = power(fact[r], mod - 2); 
    long long den2 = power(fact[n - r], mod - 2); 
    
    long long ans = (1LL * num * den1) % mod;
    ans = (1LL * ans * den2) % mod;
    return ans;
}

```

**Common C++ Syntax Gotchas**

* **Hidden integer overflow:** When multiplying two `int` variables (which can be up to $10^9$), the intermediate result can reach $10^{18}$, overflowing the 32-bit integer limits *before* the modulo is even applied.
* *Bad:* `int ans = (a * b) % mod;`
* *Good:* Force promotion to a 64-bit integer using `1LL` during the multiplication step. `long long ans = (1LL * a * b) % mod;`.
* **Note (not in video):** When solving actual CP problems, ensure your `fact` array and `precompute` function are called strictly once globally before parsing test cases so you do not recalculate $O(N)$ factorials on every single test case query.
